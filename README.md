# 지금 해볼 작업: 채팅 리팩토링

## 하고 싶은 일

이 놀이터에서 가장 먼저 해볼 작업은 채팅 리팩토링이다.

채팅을 구성하는 UI와 동작을 작은 단위로 나누고, 구조를 바꿔가며 직접 사용해본다. 실제 기능에 적용하기 전에 이곳에서 수정하고 검증하는 것이 목적이다.

놀이터 홈에서 채팅 아이콘을 클릭해 `/chat`으로 들어가 작업 결과를 확인한다.

## 시작점

현재 놀이터의 `src/features/chat/ChatPage.jsx`에는 메시지 표시, 입력창, 전송 처리, 데모 응답, 실험 설정이 한 컴포넌트에 들어 있다.

우선 이 구현을 출발점으로 삼는다. 별도의 기존 서비스 채팅을 리팩토링하려는 경우에는 해당 코드를 가져온 뒤 실제 구조와 문제에 맞춰 작업 범위를 조정한다.

## 첫 리팩토링 범위

아래는 현재 데모를 기준으로 한 초기 작업안이다.

- [ ] 현재 채팅의 동작을 확인하고 유지해야 할 동작을 정리한다.
- [ ] 메시지 목록, 메시지 항목, 입력창, 실험 설정 UI를 역할별로 분리한다.
- [ ] 메시지 전송과 대화 초기화 등 상태 처리 로직을 UI에서 분리한다.
- [ ] 데모 응답 생성 로직을 분리해 응답 구현을 교체하기 쉽게 만든다.
- [ ] 분리한 컴포넌트의 입력값과 이벤트를 정리한다.
- [ ] 리팩토링 전후 동작을 비교하고 불필요하게 복잡해진 부분을 정리한다.

컴포넌트와 훅의 구체적인 이름, 분리 수준은 작업하면서 결정한다.

## 유지하며 확인할 동작

- 메시지를 입력하고 버튼 또는 Enter로 보낼 수 있다.
- 공백만 있는 메시지는 전송되지 않는다.
- 사용자 메시지와 데모 응답이 순서대로 표시된다.
- 에코 응답과 고정 응답을 전환할 수 있다.
- 새 메시지가 추가되면 마지막 메시지로 스크롤된다.
- 메시지 간격 설정과 대화 초기화가 동작한다.
- 모바일에서도 입력과 대화 확인이 가능하다.
- 놀이터 복귀와 다른 실험실로의 이동이 동작한다.

## 완료 기준

채팅 UI와 상태 처리, 응답 생성의 역할이 구분되고, 기존 동작이 유지되면 첫 리팩토링을 완료한다. 변경한 부분은 `/chat`에서 직접 확인하고 관련 브라우저 테스트로 검증한다.

실제 AI 연결, 스트리밍, 메시지 저장 등 새로운 기능은 이번 리팩토링 이후 필요에 따라 별도 작업으로 정한다.

## 배포

GitHub Pages 주소: https://leesoyuun.github.io/Playground/

`main`에 push하면 GitHub Actions가 빌드하고 배포한다. Pages용 빌드는 `npm run build:pages`로 실행한다. 배포 환경은 HashRouter를 사용하므로 채팅 주소는 `/Playground/#/chat`이며 새로고침과 직접 접근을 지원한다. 로컬 개발은 기존 `/chat` 경로를 사용한다.
